# 架構決策紀錄（ADR）

每則 ADR 記一個決策的**背景 → 選了什麼 → 否決了什麼、為什麼不 → 代價**。格式是
[MADR 4.0](https://adr.github.io/madr/) 的中文變體：段名換成中文，語意一一對應。

與 MADR 的兩處刻意差異：

1. **代價段必填，且必須至少一條壞處。** 只寫好處的 ADR 是行銷文，不是決策紀錄。
2. **決策段第一行固定句式「選了〈X〉，因為〈一句話〉」。** 讀完整段還不知道選了什麼，是最常見的失敗。

## 兩個系列

| 系列 | 例 | 在這裡嗎 |
|---|---|---|
| `ADR-` | `ADR-0001` | 是。使用者可見行為的決策，本目錄完整收錄，號碼連續。 |
| `IDR-` | `IDR-0012` | 否。內部決策紀錄（Internal Decision Record）——詳解生成管線、模型分層、抽樣與紅隊策略等，維護者自留。 |

程式碼註解裡看到 `IDR-00XX` 而在本目錄找不到，是正常的：那是內部系列，不是掉檔。
`ADR-00XX` 則一定找得到——公開系列不留洞，這是本目錄的不變式。

## 慣例

- **已採用的不回改。** 要翻案就開新號、標「取代 00XX」，舊的標「已被取代」；回改已生效的紀錄只買到 diff 噪音。
- **不寫 ADR 的判準**（任一成立即不寫）：可逆且改回來成本低；一行程式碼註解就講得完；根本沒有真實的替代方案；純 bug 修正／命名／格式。
  反過來說一句：**「換個人接手會不會把它做錯方向？」不會，就不寫。**
